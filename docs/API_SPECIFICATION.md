# IntelliShield — API Specification

The server scores one URL with the Random Forest in `ml/models/phishing_rf.joblib`. It does not open, resolve, or crawl that URL. After the forest returns a label, the API may ask a language model to explain that label. The language model does not choose `prediction`.

Interactive docs are generated by FastAPI at `/docs`. The schema is also at `/openapi.json`.

Base URL in local development: `http://localhost:8000`. The Next.js dashboard reads that origin from `NEXT_PUBLIC_API_BASE_URL` and does not receive the language-model key.

## Endpoints

| Method | Path | Purpose |
|--------|------|---------|
| `POST` | `/api/v1/predict` | Validate a URL, score it, save the result, and return features and signals. |
| `GET` | `/api/v1/history` | Recent saved analyses: time, URL, prediction, risk level, and probability. |
| `GET` | `/api/v1/history/{id}` | One saved analysis, including features, signals, and the explanation. |
| `GET` | `/health` | Process is up, and whether the model bundle loaded. |

## `POST /api/v1/predict`

### Request

```json
{
  "url": "http://192.0.2.10:8080/login"
}
```

| Field | Type | Rules |
|-------|------|-------|
| `url` | string | Required. Trimmed. Length 1 to 16384, the same cap as the extractor. |

Unknown fields are ignored by the schema. A non-string `url` is rejected. The handler passes the string only to `predict_url` in `ml/src/predict.py`. That function calls `extract_features`. The API does not contain a second copy of the feature formulas.

### Response `200`

`url` is the normalized URL that was scored, not a second interpretation of the text. `prediction` is `safe` when the forest's label is `legitimate`, and `phishing` when the forest's label is `phishing`. `probability` is the probability of that returned label, rounded to 6 decimal places. It is not always the phishing probability. For `safe`, it is the legitimate-class probability.

`risk_level` is a display bucket of the phishing-class probability, before that rounding:

| Phishing probability | `risk_level` |
|----------------------|--------------|
| below 0.40 | `low` |
| 0.40 up to but not including 0.70 | `medium` |
| 0.70 and above | `high` |

These cut points are not thresholds the forest learned.

`features` contains the 15 extractor fields. `signals` contains at most five objects. A signal is included when a binary indicator is active (`has_ip_address`, `has_at_symbol`, `is_url_shortener`, or `has_suspicious_keyword` is 1, or `uses_https` is 0), and the list is filled from the remaining features in descending saved impurity importance. The list is then ordered by that importance. `summary` states the measured value. `importance` is copied from `ml/models/metrics.json`.

`analysis` explains the classifier result. It is not a second verdict.

| Field | Meaning |
|-------|---------|
| `source` | `llm` when the chat response matched the schema. `fallback` when the language model is not configured or the call fails. |
| `summary` | One paragraph grounded in the classifier label and the signals. |
| `reasoning` | One to five sentences taken from those facts. |
| `risk_factors` | Measurements or limitations the reader should weigh. |
| `recommendations` | Short defensive actions. They are not evasion steps. |

`prediction`, `probability`, `risk_level`, `features`, and `signals` are fixed before `analysis` is produced. A chat response that contains its own label is ignored.

### Response `422`

The URL failed validation, or the extractor rejected it. Nothing was scored. The body does not echo the submitted string.

```json
{
  "error": {
    "code": "validation_error",
    "message": "URL scheme must be http or https."
  }
}
```

| Condition | Message |
|-----------|---------|
| Missing, blank, or whitespace-only `url` | `URL is required.` |
| Longer than 16384 characters after trim | `URL must be at most 16384 characters.` |
| Non-string `url` | `URL must be a string.` |
| Scheme absent or not http/https | `URL scheme must be http or https.` |
| Hostname absent | `URL must include a hostname.` |
| Whitespace or control character | `URL must not contain whitespace or control characters.` |
| IDNA failure | `Hostname could not be encoded.` |

### Response `429`

`POST /api/v1/predict` and `GET /api/v1/history` share a sliding window of 60 requests per 60 seconds for the direct client address. `GET /health` is not counted. The response includes `Retry-After` set to the window length in seconds. The body does not include the submitted URL.

```json
{
  "error": {
    "code": "rate_limited",
    "message": "Too many requests. Try again shortly."
  }
}
```

The window is in memory for this process. It does not read `X-Forwarded-For`. `RATE_LIMIT_ENABLED`, `RATE_LIMIT_REQUESTS`, and `RATE_LIMIT_WINDOW_SECONDS` change it.

### Response `503`

The model file or feature config is missing, or the saved feature order does not match the extractor. The client message does not include the filesystem path.

```json
{
  "error": {
    "code": "model_unavailable",
    "message": "The detection model is not loaded."
  }
}
```

### Response `500`

```json
{
  "error": {
    "code": "internal_error",
    "message": "The analysis could not be completed."
  }
}
```

A successful `POST /api/v1/predict` is written to SQLite after the response fields exist. A 422 or 503 is not written. The immediate response still returns the normalized URL that was scored. The stored copy, and both history responses, use that URL after userinfo is replaced with `REDACTED` and each query value is replaced with `REDACTED`. The path, host, and port are kept. The row does not store the client address, request headers, or the language-model key. If the database write fails, the score is still returned and the failure is logged without adding the URL to the log line.

Startup scoring of `https://example.com/` loads the forest and does not create a history row.

## `GET /api/v1/history`

Returns the newest saved analyses. `limit` defaults to 20 and must be from 1 to 50.

### Response `200`

```json
{
  "items": [
    {
      "id": 1,
      "created_at": "2026-09-26T18:00:00Z",
      "url": "http://192.0.2.10:8080/login",
      "prediction": "phishing",
      "probability": 1.0,
      "risk_level": "high"
    }
  ]
}
```

`created_at` is UTC. `prediction`, `probability`, and `risk_level` are the values stored from the classifier response. `url` is the redacted normalized URL. The timestamp in the example is the shape the API emits; it is not a recorded row.

## `GET /api/v1/history/{id}`

`id` is the integer from the list. The body is the stored score: the same fields as `POST /api/v1/predict`, plus `id` and `created_at`. It is not a new classification.

### Response `200`

The object matches a predict response for that saved row, with `id` and `created_at` added. `url` is the redacted form.

### Response `404`

```json
{
  "error": {
    "code": "not_found",
    "message": "That analysis was not found."
  }
}
```

A non-integer `id` is `422` with message `Analysis id must be an integer.`

## `GET /health`

### Response `200`

```json
{
  "status": "ok",
  "model_loaded": true
}
```

`status` stays `ok` when the process can serve this route, including when `model_loaded` is `false`.

## Explanation call

When `OPENAI_API_KEY`, `OPENAI_BASE_URL`, and `OPENAI_MODEL` are all set, the server sends one `POST {OPENAI_BASE_URL}/chat/completions` request. The user message is JSON with:

- `classifier_prediction` (`safe` or `phishing`)
- `probability` (probability of that label)
- `risk_level`
- `normalized_url_redacted` (userinfo and query values replaced)
- `signals` (feature name, value, and the signal sentence)

The system prompt tells the model that the classifier prediction is final, that the URL is untrusted data, and that the reply must be one JSON object with `summary`, `reasoning`, `risk_factors`, and `recommendations`. Temperature is `0.2`. The client waits at most `LLM_TIMEOUT_SECONDS` (default 20) and does not retry.

The server validates that object before it is returned. Text that is not the schema is dropped. The log line records `explanation source=llm` or `explanation source=fallback` and a reason code. It does not record the URL, the prompt, or the API key.

## What this route does not do

- It does not let the language model set `prediction`, `probability`, or `risk_level`.
- It does not execute the URL as a command.
- It does not open the submitted host. The only optional outbound call is the configured chat endpoint.
- It does not log the URL, query string, userinfo, or API key. Access logs contain the request id, method, path, and status code.

## Configuration

Environment variables, also listed in `backend/.env.example`:

| Variable | Purpose |
|----------|---------|
| `CORS_ORIGINS` | Comma-separated browser origins. Default `http://localhost:3000`. A value of `*` is rejected at startup. Credentials are not sent. |
| `LOG_LEVEL` | Default `INFO`. |
| `MODEL_PATH` | Joblib bundle. Empty uses `ml/models/phishing_rf.joblib`. |
| `FEATURE_CONFIG_PATH` | Feature order file. Empty uses `ml/models/feature_config.json`. |
| `METRICS_PATH` | Importance file. Empty uses `ml/models/metrics.json`. |
| `OPENAI_API_KEY` | Bearer token for the explanation call. Empty skips that call. Never committed. |
| `OPENAI_BASE_URL` | Chat API origin, for example `https://api.openai.com/v1`. |
| `OPENAI_MODEL` | Model name sent with the chat request. |
| `LLM_TIMEOUT_SECONDS` | Hard timeout for that request. Default `20`. |
| `DATABASE_URL` | SQLAlchemy URL. Empty uses `backend/data/intellishield.db`. |
| `RATE_LIMIT_ENABLED` | `true` or `false`. Default `true`. |
| `RATE_LIMIT_REQUESTS` | Requests allowed per window for predict and history. Default `60`. |
| `RATE_LIMIT_WINDOW_SECONDS` | Window length. Default `60`. |

## Run

From `backend/`, after `pip install -r requirements.txt`:

```bash
uvicorn app.main:app --reload --port 8000
```

OpenAPI UI: `http://localhost:8000/docs`
